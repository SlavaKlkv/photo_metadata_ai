## Структура

| Файл | Назначение |
| --- | --- |
| `index.html` | Главная |
| `screens.html` | Галерея экранов |
| `ambient-particle-flags.js` | Флаги летающей частицы (`index` / `screens` отдельно) |
| `brand-iris/` | Диафрагма логотипа в шапке: наведение раскрывает затвор, нажатие захлопывает |
| `header-swap.js` | Плавная смена пунктов шапки index ↔ screens (клик); бренд не гаснет (FLIP в `brand-iris/`) |
| `icon.svg`, `og.png` | Фавикон и OG-картинка |

> [!NOTE]
> Это чистый HTML без сборки и без `.env`: браузер и Pages не подхватывают
> env-переменные приложения. Конфиг лендинга — прямо в странице (или в этом README).

## Две отдельные страницы, без общего шаблона

`index.html` и `screens.html` — **два самодостаточных HTML-документа**. Общего
layout/partial (`header.html`, `_base`, include через SSG) нет: у каждой страницы
свои `<head>`, стили, разметка и скрипты.

### Зачем так

| Причина | Суть |
| --- | --- |
| **Без сборки** | Лендинг живёт на GitHub Pages из `docs/`: открыл HTML — готово. Шаблон (eleventy, jinja, partials) потребовал бы шаг генерации, который здесь сознательно не нужен. |
| **Разные задачи** | Главная — маркетинговый сценарий (hero, CTA, FAQ, установка). `screens.html` — галерея скриншотов: другая структура, другой объём CSS/JS, другой SEO (`canonical`, title, description). |
| **Изоляция регрессий** | Правка галереи не ломает главную и наоборот. Общий шаблон дал бы связанность там, где страницы почти не пересекаются. |
| **Прозрачность диффа** | Весь код страницы в одном файле: ревью и правки без охоты по partial'ам. |

### Что «общего» всё же есть

Не полный шаблон, а **сознательный дубляж контракта** и один файл флагов частицы:

- палитра и токены (`:root` / CSS-переменные) — визуально одна система;
- sticky-шапка, тёмный canvas, favicon / OG;
- флаги ambient-частицы — [`ambient-particle-flags.js`](./ambient-particle-flags.js):
  одна точка правки, **значения разделены по страницам**;
- диафрагма логотипа — [`brand-iris/`](./brand-iris): один набор модулей на обе шапки;
- смена шапки между страницами — [`header-swap.js`](./header-swap.js) + ранний
  inline-маркер `header-swap`: fade соседей бренда, бренд едет FLIP-ом
  ([`brand-iris/`](./brand-iris)); только клик peer, без View Transition API.

> [!WARNING]
> При смене цветов обновляйте **оба** HTML. Флаги частицы правятся только
> в `ambient-particle-flags.js` (блоки `index` / `screens`).

## Диафрагма логотипа

Метка в шапке — не картинка, а процедурно построенный ирис: корпус, кольцо отверстия
и шесть кромок-лепестков, каждая из которых остаётся касательной к отверстию. Лепестки
сидят на кривошипе, поэтому одновременно проворачиваются и меняют отверстие — у краёв
хода механизм замедляется сам, как в объективе.

Файлы лежат в [`brand-iris/`](./brand-iris) и подключаются обычными `<script>` именно
в этом порядке — сборки на лендинге нет, модули общаются через глобальную область
(в тестах ту же роль играет `globalThis`):

| Модуль | За что отвечает |
| --- | --- |
| `geometry.js` | Размеры, кинематика лепестков, путь метки. Только числа, без DOM |
| `motion.js` | Характер каждой фазы (спуск, раскрытие, возврат) и покадровая отрисовка |
| `handoff.js` | `sessionStorage` между страницами и FLIP-переезд бренда |
| `presence.js` | Единственный ответчик на вопрос «указатель на бренде?» |
| `init.js` | Состояние метки и события шапки |

### Три состояния

Весь ход — одно число: `−1` раскрыто, `0` покой, `+1` затвор закрыт.

| Событие | Что делает затвор | Куда приходит |
| --- | --- | --- |
| Наведение или фокус | плавно раскрывается (`OPEN_MS`) | раскрыт (−1) |
| Нажатие, Enter, пробел | захлопывается рывком (`SHUT_MS`) и залипает | закрыт (+1) |
| Уход курсора | возвращается с отдачей пружины (`REST_MS`) | покой (0) |
| Тап (`hover: none` / `pointer: coarse` / `pointerType=touch`) | плавно раскрыть (`OPEN_MS`, как наведение) → закрыть (`SHUT_MS`) → держать до конца скролла/`#top` или peer-перехода | покой (0) |

Все три состояния выводятся из двух фактов — указатель (или клавиатурный фокус) на бренде
и спущен ли затвор:

| Указатель / фокус | Затвор спущен | Метка |
| --- | --- | --- |
| нет | — | покой (0), фиксация снимается |
| да | да | закрыт (+1) |
| да | нет | раскрыт (−1) |

Поэтому положение задаётся в одном месте — `applyPose()`, а обработчики только меняют
факты. Раньше каждый дёргал метку сам, и любой новый краевой случай ломал соседние:
щелчок то держался, то раскрывался под неподвижным курсором.

**Залипание снимает только уход курсора.** Отпускание кнопки затвор не раскрывает
(`mouseup` не слушается), и потеря фокуса — тоже: клик по логотипу ведёт на `#top`,
а переход к якорю снимает с ссылки фокус, из-за чего метка захлопывалась и тут же
возвращалась в покой прямо под курсором. По `blur` метка сбрасывается, только если
курсора на бренде нет.

**Без скрипта метка не ломается.** При `t = 0` путь совпадает с меткой из `icon.svg` —
она же лежит в разметке страниц, поэтому без JS и при `prefers-reduced-motion` логотип
остаётся ровно таким, каким свёрстан. Размеры и тайминги — в `BRAND_IRIS`
(`brand-iris/geometry.js`).

### Смена шапки (peer index ↔ screens)

Fade-out → переход → fade-in соседей бренда (~220 ms / ~320 ms). Бренд не гаснет,
едет FLIP-ом. In-page (якоря `#features` и т.п., появление «Скачать» в шапке) —
**полный fade шапки не делаем**: у якоря/скролла меняется только opacity кнопки `.nav-cta`.

При **клике** peer index ↔ screens:

1. Соседи гаснут (`header-swap-out`, ~220 ms); **бренд остаётся**.
2. Флаг enter + handoff диафрагмы (sessionStorage — та же вкладка; localStorage —
   новая вкладка `target=_blank` с главной).
3. Та же вкладка: navigate. Новая: `window.open`, исходная шапка возвращается;
   на arrival early-скрипт ставит `html.header-swap` → ready, FLIP, fade-in (~320 ms).

Back/Forward и F5 fade **не** делают.

**Метка появляется сразу в конечном положении** (`saved.to`), а не там, где её застал
переход: щелчок случился на покинутой странице, его ход виден там же. Иначе новая
страница на кадр показывала покой и только потом захлопывалась — вспышка на самом
видном месте шапки.

> [!NOTE]
> View Transition API намеренно не используем — в Chrome он вспыхивал при возврате.

Дальше всё решает `presence.js` — «указатель на бренде?». Смена документа уходом курсора
**не считается**: браузер пересобирает hover нового документа и присылает `mouseleave`,
хотя указатель с логотипа не двигался, а `:hover` остаётся пустым до первого движения мыши.

<details>
<summary><b>Почему присутствие определяется зоной, а не hit-test'ом</b></summary>

Судить по hit-test в это время нельзя: бренд скрыт под `header-swap` и едет FLIP-ом,
поэтому `elementFromPoint` не находит его даже под самым курсором.

Поэтому на окно прибытия (`brandIrisArriveMs()` — переезд бренда, но не меньше
`SETTLE_MS`) присутствие определяет **зона**: прямоугольник, охватывающий место бренда
на покинутой странице и его место здесь, с допуском `ZONE_PAD`.

| Точка курсора | Вывод |
| --- | --- |
| внутри зоны | курсор никуда не уходил, `mouseleave` фантомный |
| снаружи | мышь действительно уехала — метка идёт в покой сразу, не дожидаясь конца окна |

Зона решает и краевые случаи вроде клика по последней букве wordmark: там точка у самой
границы, и hit-test во время переезда её теряет.

Если координат нет вовсе (мышь не двигалась ни разу), верим покинутой странице: ненулевая
цель хода означает, что указатель был на бренде, и щелчок обязан доиграть здесь. В конце
окна метка сверяет положение курсора — но только если за всё окно не пришло ни одного
достоверного сигнала (`mouseenter`, `mouseleave`, движение мыши). Иначе она переспрашивала
бы у пустого `:hover` и сама себя опровергала: затвор снимался с фиксации, и первое же
движение его раскрывало.

</details>

Запись handoff живёт `HANDOFF_TTL` и расходуется один раз.

## OG-картинка собирается из мокапа главной

`og.png` — не отдельный макет: окно приложения на ней рендерится из блока `.hero-visual`
самой `index.html` вместе со всеми стилями страницы. Поэтому мокап живёт в одном месте,
а картинку достаточно пересобрать:

```bash
cd desktop && npm run build:og
```

Скрипт — [`desktop/scripts/build-og.js`](../../desktop/scripts/build-og.js): рендерит
страницу в headless Chrome (1200×630 при `--force-device-scale-factor=2` → 2400×1260,
ровно как объявлено в `og:image:width/height`) и перезаписывает `og.png`. Анимации входа
и «плавания» глушатся через `prefers-reduced-motion`, иначе окно попадёт в кадр
в случайной фазе.

> [!TIP]
> Если Chrome лежит не в `/Applications`, путь задаётся переменной `CHROME_PATH`.

Чтобы не помнить об этом вручную, есть pre-commit хук — пересобирает `og.png` и добавляет
его в коммит, если в коммит попала `docs/landing/index.html`:

```bash
cd desktop && npm run hooks:install
```

| Деталь хука | Как есть |
| --- | --- |
| Исходник | [`desktop/scripts/hooks/pre-commit`](../../desktop/scripts/hooks/pre-commit) |
| Куда ставится | `.git/hooks` (в worktree — общий каталог хуков репозитория) |
| Чужой хук | с тем же именем не перезаписывается без `--force` |
| Отключить | удалить `.git/hooks/pre-commit` |
| Машина без Chrome | коммит не рушится, печатается предупреждение |

## Переключатели ambient-частицы

Файл: [`ambient-particle-flags.js`](./ambient-particle-flags.js)
Маркер для поиска: `LANDING_PARTICLE_FLAGS`.

| Флаг | Смысл |
| --- | --- |
| `ENABLE_AMBIENT_PARTICLE` | Вся летающая частица. `false` — элемент убирается из DOM, анимация и слушатели не стартуют. |
| `ENABLE_HOVER_ATTRACTION` | Притяжение пятна к курсору. Код follow остаётся; `true` снова включает захват. |

Значения **не общие на весь лендинг**: у `index` и `screens` свой набор. Можно выключить
частицу только на главной, только в галерее или настроить hover независимо.

**Как править.** `true`/`false` в объекте `LANDING_PARTICLE_FLAGS.index` или `.screens`
в `ambient-particle-flags.js`. HTML-страницы сами не задают значения — только выбирают
ключ (`getLandingParticleFlags('index')` / `getLandingParticleFlags('screens')`).

> [!NOTE]
> `prefers-reduced-motion: reduce` по-прежнему отключает частицу на стороне CSS/JS
> независимо от этих флагов.
