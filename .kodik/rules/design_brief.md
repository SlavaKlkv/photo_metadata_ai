## 1. Пользовательские сценарии (User Flow)
Пользователь — фотограф, который хочет подготовить фотографии для загрузки на фотостоки (Getty, Shutterstock, Adobe Stock). Продукт не требует регистрации и авторизации.

### Сценарий 1. Основной — обработка фотографий и экспорт CSV
Описание: пользователь загружает фотографии, AI генерирует метаданные, пользователь скачивает CSV.

1. Пользователь открывает веб-приложение в браузере.
2. На экране отображается drag-and-drop зона для загрузки фотографий.
3. Пользователь перетаскивает папку с фотографиями (50+ файлов) в зону загрузки.
4. Система отображает превью миниатюр загруженных файлов. //Этот функционаал не нужен
5. Пользователь вводит контекст съёмки в текстовое поле (опционально). Например: "Свадьба, май 2026".
6. Пользователь выбирает AI-провайдера из выпадающего списка: Ollama (по умолчанию), Claude, OpenAI.
7. Пользователь нажимает кнопку "Start Processing".
8. Система начинает обработку файлов. Каждый файл получает статус: Queued → Processing → Done / Error.
9. Прогресс отображается в режиме реального времени для каждого файла.
10. После завершения обработки пользователь видит таблицу с результатами: исходное имя, новое имя файла, заголовок, описание, ключевые слова.
11. Пользователь при необходимости редактирует метаданные прямо в таблице.
12. Пользователь нажимает кнопку "Export Results".
13. Система генерирует CSV-файл и запускает скачивание.
14. Пользователь получает готовый CSV для загрузки на фотосток.

### Сценарий 2. Ошибка при обработке файла
Описание: один или несколько файлов не удалось обработать.

15. Пользователь загружает файлы и запускает обработку.
16. Один из файлов имеет неподдерживаемый формат или повреждён.
17. Система помечает этот файл статусом Error и отображает причину ошибки.
18. Остальные файлы продолжают обрабатываться без прерывания.
19. Пользователь видит итоговую таблицу — файл с ошибкой отмечен, остальные готовы к экспорту.
20. Пользователь экспортирует CSV только по успешно обработанным файлам.

### Сценарий 3. Недоступность основного AI-провайдера
Описание: Ollama недоступен, система переключается на OpenAI автоматически.//Нет, здесь пользователь должен выбрать

21. Пользователь запускает обработку с выбранным провайдером Ollama.
22. Ollama API недоступен или превышено время ожидания.
23. Система запрашивает у пользователя выбрать другой AI //Исправлено!
24. Обработка продолжается в штатном режиме.
25. Пользователь получает результаты и скачивает CSV.

## 2. Список экранов
Ниже перечислены все экраны которые необходимо отрисовать. Указан приоритет для MVP — экраны с приоритетом "Высокий" необходимы для демо 18.05.2026.

| N | Название экрана | Описание | Приоритет |
| :--- | :--- | :--- | :--- |
| 1 | Главный экран | Drag-and-drop зона загрузки фотографий. Счётчик загруженных файлов. | Высокий |
| 2 | Панель настроек | Текстовое поле "Контекст съёмки". Dropdown выбора AI-провайдера (Ollama, Claude, OpenAI). Выбор платформы экспорта (Getty, Shutterstock, Adobe). | Высокий |
| 3 | Статус обработки | Progress bar с индикатором статуса: Queued, Processing, Done, Error. Progress bar — один для всех файлов. Отображение причины ошибки для файлов со статусом Error. | Высокий |
| 4 | Таблица превью метаданных | Таблица с результатами: исходное имя, новое имя файла, заголовок, описание, ключевые слова. Inline-редактирование ячеек. Кнопка "Preview All". | Высокий |
| 5 | Экспорт | Кнопка "Export Results". Индикация успешного скачивания CSV. | Высокий |
| 6 | Состояние ошибки | Отображение ошибки при недоступности AI-провайдера. Уведомление об автоматическом переключении на резервный провайдер. | Средний |
| 7 | Пустое состояние | Экран до загрузки файлов — подсказка пользователю что нужно сделать. | Средний |

### 2.1 Приоритет экранов для MVP
К демо 18.05.2026 обязательны экраны 1–5. Экраны 6–7 желательны но не блокируют демо.

### 2.2 Референс
Анастасия подготовила мокап интерфейса — доступен в общем чате команды. Рекомендуется использовать как отправную точку, не как финальное решение.
Ключевые элементы из мокапа: тёмная тема, четыре блока на главном экране (загрузка, настройки, контекст, статус), таблица превью внизу, три кнопки действий.

### 2.3 Пожелания команды
- Интерфейс должен быть понятен без инструкции — пользователь сразу видит что нужно сделать.
- Акцент на drag-and-drop зоне — это главное действие.
- Статус обработки должен быть виден без скролла.
- Таблица с результатами должна легко читаться при большом количестве файлов.
